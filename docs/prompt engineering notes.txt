Chapter 6: Precognition (Thinking Step by Step)
What you learn:

"Chain of thought" reasoning: ask Claude to show its work
Why this matters: more accurate, more reliable, better for complex problems
How step-by-step reduces hallucination
Trade-off: uses more tokens (costs more, slower)
Key Concept:

Code
❌ Direct extraction:
"What is the ER status?"
Response: "Positive"
(We don't know HOW Claude decided this)

✅ Chain of thought:
"Walk me through your reasoning:
1. Find all statements about ER status
2. Identify the most authoritative source
3. Note any conflicting information
4. Conclude with your final answer"

Response:
1. I found three mentions:
   - Line 5: "ER staining is positive"
   - Line 12: "Initial ER test was inconclusive"
   - Line 18: "Confirmatory ER test: >90% positive"
2. The most authoritative is the confirmatory test (line 18)
3. No significant conflicts (initial inconclusive result superseded)
4. Final answer: POSITIVE
For your fabrication detection: If you use CoT (your P2 prompt), you can:

Ask Claude to cite each evidence chunk it used
Request explicit reasoning for confidence scores
Detect hallucinations by checking if evidence actually supports the conclusion

def node_chain_of_thought(state: ExtractionState) -> ExtractionState:
    prompt = """
    Step 1: Find all mentions of {element} in the document
    Step 2: Identify the most authoritative statement
    Step 3: Note any conflicting information
    Step 4: Return JSON with:
      - value: your conclusion
      - reasoning: your step-by-step logic
      - confidence: 0-1 based on clarity and agreement
    """
    result = call_claude(state['text'], prompt)
    return state
Chapter 7: Using Examples (Few-Shot Prompting)
What you learn:

How to include examples within your prompt (few-shot learning)
Why examples clarify exactly what you want
How well-crafted examples dramatically improve consistency
Trade-offs: more tokens used, but better quality
Key Concept:

Code
❌ Zero-shot (no examples):
"Extract ER status"

✅ Few-shot (with examples):
"Extract ER status. Here are examples of correct extraction:

EXAMPLE 1:
Source: 'ER immunohistochemistry: Positive (95%)'
Output: {"value": "positive", "evidence": "Immunohistochemistry shows 95% positive", "confidence": 0.96}

EXAMPLE 2:
Source: 'Estrogen receptor testing was not performed on this specimen'
Output: {"value": "unknown", "evidence": "ER testing not performed", "confidence": 1.0}

EXAMPLE 3:
Source: 'ER status unclear; initial test equivocal, confirmatory test pending'
Output: {"value": "unknown", "evidence": "Initial test equivocal, confirmatory test pending", "confidence": 0.4}

Now extract ER status from: [NEW DOCUMENT]"
For your project: Your few-shot prompts (P4) would include:

Code
- 2–3 examples of correct extraction per element
- Handling of edge cases (missing data, conflicting info, equivocal results)
- Examples of both positive and negative extractions
Why effective for clinical extraction:

Medical terminology is precise; examples help Claude use it correctly
Edge cases (equivocal results) need to be shown, not described
Improves consistency across all 200 cases

Chapter 8: Avoiding Hallucinations
What you learn:

Why Claude hallucinates (generates plausible-sounding but false information)
Practical mitigation strategies:
Demand citations — "Quote the exact source text"
Restrict to retrieved context — "Only use the provided chunks"
Set boundaries — "Return 'unknown' if not found, never guess"
Check answers — "Does your answer match the source text?"
How RAG reduces hallucination by limiting context
Key Concept:

Code
Hallucination example:
Source: "ER testing: Positive"
(No mention of specific percentage)

Hallucinated response: "ER status is positive (92%)"
(Claude invented the 92% because it's plausible)

Prevention:
"Return ONLY information explicitly stated in the source.
If you invent any data point, return null/unknown instead."

Measurement for your paper:

Code
Fabrication rate = FP / (FP + TN)

Where:
FP = Claude said "present" (fabricated)
TN = Claude correctly said "not found/unknown"

Example: If source has 50 elements marked "not present":
- Claude correctly returned "unknown": 45 (TN)
- Claude hallucinated a value: 5 (FP)
- Fabrication rate = 5 / 50 = 0.10 (10%)
